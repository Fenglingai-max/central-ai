# 两个技能如何整合到 Central.ai

> 当前整合的是网页交互、结构化数据与确定性规则。没有在浏览器内运行 Codex 技能执行器，也未把本地模板冒充 AI 创作。真实文本、图像和视频生成 API 仍待接入。

## 来源与版本

| 技能 | 版本 | 本次来源 |
| --- | --- | --- |
| `realistic-character-sheet`（真实人物资产） | 2.0.1 | 用户提供的 `SKILL.md` 及本地同版本参考说明 |
| `short-drama-prompts`（短剧提示词导演） | 1.0.1 | 用户提供的 `SKILL.md`、导演/摄影、输出、数据、资产与即梦适配参考说明 |

这些技能是创作与检查流程，不是已连接的供应商 API。Central.ai 的输入、提示词、资产索引、分场及下一页视频请求沿用其规则。界面没有声称仅通过一次模板编译就完成完整导演创作或真实人物出图。

## 网页工作流

```text
主题 / 故事大纲
  + 用户选定视觉风格
  + 人像 / 风格 / 服装参考
  + 可选角色、地点、道具、原始对白
                 ↓
选择：角色资产 / 道具资产 / AI 提示词 / 完整创作包
                 ↓
创作包与结构校验（当前是本地可编辑草案）
                 ↓
第二页：资产、分镜、独立 30 秒提示词与检查状态
                 ↓
视频模型 + 文生/图生输入 + 参数校验 + 草稿导出
                 ↓
供应商提交与真实产物审核（API 待接入）
```

角色/道具模式仅将对应类别标为 `requested: true`；关联场景和其他资产可以保留在内部结构，避免引用断裂，但不声称它们是本次请求的图片。提示词模式交付文本，无需自动出图。完整模式未来应包含实际图片；当前图片均为空并明确待生成。

## 已映射的关键规则

### 真实人物资产

- 每个角色独立身份。默认虚构成年人；没有真人照片时不称“真实路人”或“真实拍摄”。
- 默认横向 16:9 人物资产：左约 40% 正面胸像，右约 60% 同一人的正面、严格 90° 侧面、背面全身。全身尺度、头顶/脚底基线一致，不裁头脚。
- 以自然生活感、可辨识脸部关系与合理穿搭为目标，不默认明星脸、网红妆或模特比例；不把普通人写成丑化、衰老或邋遢。
- 人像参考锁定身份；服装参考仅沿用结构；风格参考用于光色和美术。参考用途在界面与索引中区分。
- 人物资产采用中性柔和光、灰白背景和自然透视。剧情中的强烈风格光不替代清楚的身份参考图。
- 服装实款匹配未完成时明确待核验；没有虚构商品 SKU、材质成分、图像查看记录或“同款复刻”结论。
- 身份、服装结构、方向、道具结构或质感出错应重新生成该张，首版后默认至多两轮；不能仅凭重生成就认定审核通过。

### 短剧提示词导演

- 用户的主题和风格是创作输入；风格未确认时保持“待确认”，不自行锁定题材、地域或摄影审美。
- 原始大纲完整保留。当前本地引擎不做语义分析，缺少角色/地点/道具时仅建立明确待替换的槽位。
- 新剧应先完成可见钩子、目标、阻力、失败代价、反转证据和可见结果，再锁定对白。当前模板只提示这些创作位置，没有把它们伪装成已完成故事。
- 已提供的锁定台词逐字保留说话人、原文与顺序；跨镜分片后仍须拼接回同一原句。长对白超出时长预算时报错，不删改原文。
- 每场严格 30 秒；镜头连续、无重叠无缺口，单镜 2–5 秒。当前 UI 可选 30 / 60 / 90 / 120 秒，引擎严格模式可接受 30–600 秒的 30 整倍数。
- 景别仅用远景、全景、中景、近景、特写、大特写；运动仅用推、拉、摇、移、跟、固定；平视、俯拍、仰拍独立记录。
- 每镜记录焦距、光圈、焦点、机位高度、主体距离及运动方向/终点。这些是摄影意图，不能保证生成模型精确执行。
- 从同一份镜头数据编译每场独立的大段提示词。每段自足展开风格、画幅、人物描述、地点、道具、起止状态与连续性，不使用“同上”代替设定。
- 角色、地点、道具分别使用 C / L / P 编号；动态状态与身份/结构分开。主轴、视线、人物自身左右手、入出画方向、道具归属和主光方向需连续。
- 场景和道具提示词明确无人、无手、无肢体、无人像海报/屏幕人脸/镜面人影。剧情必需的人像证据应另建例外资产，当前尚无该专项编辑器。
- 30 秒是主生产单元。视频页可按模型时长沿原分镜边界拆分；不把 2–5 秒镜头长度当作所有平台支持的单次时长。

## 实现文件与数据

| 文件 | 责任 |
| --- | --- |
| `src/engine.js` | 输入归一化、确定性结构草案、资产提示词、对白分配、时长/资产/对白校验、Markdown/JSON 导出 |
| `src/models.js` | 已注明核验时间的模型目录、通用视频请求草稿、时长/参数组合校验、按镜头边界拆分 |
| `src/app.js` | 两页交互、参考上传预览、本地项目、模型选择、输入框及导出 |
| `tests/engine.test.js` | 时长连续性、对白原文、模式范围、参考来源、错误数据及完整导出测试 |
| `docs/API.md` | 后续服务端、上传、生成、任务与审核状态契约；明确未实现部分 |

引擎沿用短剧技能数据结构：`total_seconds`、`prefix`、`visual_style`、`aspect_ratio`、`locked_dialogue`、`assets`、`scenes`。人物资产独立保留 `aspect_ratio: "16:9"`，不受成片竖屏设置影响。参考只保存已知元数据，不在导出项目中嵌入本地参考像素并声称已被模型读取。

## 已做的验证与限度

- 引擎单元测试覆盖：严格时长、无缝镜头、模式请求范围、跨镜对白逐字/顺序/Unicode 保留、超时对白拒绝、参考来源状态、错误 ID/摄影参数/运镜检测和完整文本导出。
- 对引擎生成的 60 秒、两场、含对白 JSON，实际运行原技能 `scripts/compile_prompts.py`，结构校验通过。
- 以上验证只证明结构与编译符合相应约定，不能证明故事有戏、反转成立、摄影可执行、图片自然或供应商任务必然成功。

## 当前仍缺少的完整创作能力

1. 主题语义理解与真正故事创作：目标/阻力/代价、铺垫、反转、完整剧本及导演修订。
2. 原始剧本的可靠对白提取与确认；目前精确锁定依赖用户提供的逐句对白，不自动改写大纲中的句子。
3. 实款服装检索、实际查看商品图、记录结构并真实送入图像服务。
4. 真实人物身份候选、四视角图、状态图、无人场景与无人道具图的生成。
5. 实际图像查看、身份/服装/方向/空间/道具/质感审核及至多两轮重新生成。
6. 最终通过的图片回填资产索引、分镜与提示词；当前没有图片可据此锁定或回填。
7. 真实供应商任务、上传、鉴权、异步状态、音画与口型审核、视频下载及多段拼接。
8. 非 30 整倍数时长的明确尾段策略；当前严格模式会拒绝，不偷偷补空镜或修改总长。

这些缺失在页面和导出文件中保持可见。后续接入应逐项实现并更新真实状态，不能将“结构通过”改写为“全部生成并审核完成”。
